# PoE Craft Guard — контекст проекта для Claude Code

Инструмент для крафта в Path of Exile 1 (Windows, английский клиент). Читает подсказку
предмета с экрана (Windows OCR), сопоставляет строки с модами и тирами из данных игры
и **блокирует левый клик**, когда на предмете выпала цель. Общение с пользователем и
весь UI — на русском.

## Жёсткое правило: программа не создаёт ввод

Правило GGG: одно нажатие человека — одно действие на сервере. Поэтому:
- программа **никогда** не кликает и не жмёт клавиши за пользователя (никаких автороллеров,
  «держи кнопку — сферы кидаются сами», рандомизации интервалов и т. п.). Пользователь
  уже просил такое — это отклонено и не обсуждается;
- разрешено только **подавлять** ввод: глотать ЛКМ (блок после попадания, пошаговый режим)
  и не передавать отпускание Shift (Shift-замок);
- единственное синтетическое событие — отпускание Shift при снятии замка, чтобы клавиша
  не осталась зажатой в системе.

## Данные

Источник — `https://raw.githubusercontent.com/repoe-fork/repoe-fork.github.io/master/data/`
(экспорт файлов игры, обновляется под каждый патч; на момент написания 3.30.0.4):
`mods.json`, `base_items.json`, `stat_translations.json`, `cluster_jewels.json`.

Ключевые факты о данных:
- влияние мода = тег в `spawn_weights`: `<тег базы>_basilisk` Hunter, `_eyrie` Redeemer,
  `_adjudicator` Warlord, `_crusader` Crusader, `_shaper`, `_elder`;
- элевейтед-моды (`...Maven`) имеют вес 0 — подключаются как «сиблинги» обычных модов влияния;
- теги мода (`implicit_tags`: attack, critical, life, defences…) — на них ориентируются
  Harvest-реформы. Условные моды тег по условию не получают (Tailwind без тега critical,
  Elusive on Crit — с тегом critical);
- у кластеров пул нотаблов задаётся энчантом: строка «Added Small Passive Skills grant: …»
  → `cluster_jewels.json` → тег (`affliction_*`), моды из домена `affliction_jewel`.

## Как работает распознавание

1. **Шаблоны.** Для каждого мода пула из `stat_translations` строится строка-шаблон и «скелет»
   (текст без чисел, нижний регистр). Учитываются условия вариантов перевода,
   `index_handlers` (negate, divide_by_…), разметка `[A|B]`, числа прямо в тексте шаблона
   и плейсхолдеры с format `ignore` (проверка значения отключена).
2. **Сопоставление.** Строка OCR → скелет → точное совпадение или `difflib` (порог 0.86).
   Числа извлекаются только отдельно стоящие (цифра внутри слова — шум OCR).
   Первая строка, похожая на имплисит базы, пропускается (тоже нечётко).
   Многострочные моды (гибриды, элевейтед) назначаются первыми, строки не переиспользуются.
3. **Тир** = место среди модов той же группы (`type`, влияние, префикс/суффикс, элевейтед),
   по убыванию required_level. Совпадает с игрой (проверено: Mana T9, Rarity T2).
   При пересечении диапазонов показывается «T2/T3», правило берёт лучший.
4. **Шанс** = вес мода / сумма весов доступных на этом ilvl префиксов (суффиксов) базы.

## Конвейер в `app.py`

захват области (mss) → сигнатура кадра (порог изменений `CHANGE_THRESHOLD`) →
OCR сразу на первом заметном изменении → сопоставление → правило → блок ЛКМ + сигнал.

- `FastOCR`: движок Windows OCR создаётся один раз (вызов `winocr.recognize_pil_sync`
  на каждый кадр был главным тормозом); строки возвращаются с координатами.
- Калибровка (F8): область ~1700×1450 вокруг курсора в пределах монитора — подсказка бывает
  над предметом (тайник) и сбоку/ниже (станок Harvest). Сохраняется в `config.json`.
- Автообрезка: после первого удачного распознавания захват и OCR идут только по области
  подсказки; если строка мода у края обрезки или модов не найдено — снова полный кадр.
  Типичное время на ролл после обрезки: 40–50 мс.
- Пошаговый режим: после пропущенного клика следующий глотается, пока не распознаны моды
  нового ролла (таймаут `PENDING_TIMEOUT` 1.5 с).
- Shift-замок: при включённой охране первый ЛКМ с зажатым Shift «защёлкивает» Shift —
  его отпускание не передаётся (`suppress_event` в keyboard-хуке). Снимается новым
  нажатием Shift, выключением охраны, закрытием программы.

## Выпуск и обновление

- Выпуск: поднять `VERSION` в `updater.py`, раздел `## X.Y.Z` в `CHANGELOG.md`, коммит в `main`,
  тег `vX.Y.Z` (из облачной сессии Claude тег не пушится — выпуск создаётся через `gh api …/releases`) → `.github/workflows/release.yml` проверит версию, прогонит тесты обновления и создаст
  GitHub Release с текстом из CHANGELOG.
- Программа: «⚙ Настройки» → «О программе» (версия, «Что нового», «Сообщить об ошибке», проверка).
  Автообновление (`auto_update`, по умолчанию on): проверка при запуске (через 5 с) и раз в 6 ч,
  новая версия ставится сама, работает после перезапуска. Состояние — `config.json` → `update`.
- Проверка идёт без токена через api.github.com — **репозиторий должен быть публичным**, иначе 404.

## Тестирование

- Ядро: `python tests/test_moddb.py` (или pytest). Образцы предметов — в `tests/samples/`.
- GUI можно прогнать без Windows: заглушки модулей `mss`, `pyperclip`, `winocr`, `winsound`,
  `pynput` + `xvfb-run` и скриншоты через `PIL.ImageGrab`. Windows-части (OCR, хуки,
  захват) проверяются только у пользователя — проси скриншот журнала или вывод F10.

## Пользователь и его сетап

- PoE 1, лига Covens (3.30), английский клиент, оконный режим 1920×1009,
  рядом Awakened PoE Trade (его F9 = выход из игры, поэтому охрана на F6).
- Крафтит ботинки Hunter/Redeemer (элевейтед Tailwind + элевейтед Elusive через
  Orb of Dominance, Hinekora's Lock через бистов, Awakener's Orb с предпросмотром),
  Harvest Reforge, эссенции, кластеры.
- Предпочитает коротко и по делу; отказывается от «лишних» фич — сначала спроси, нужно ли.

## Идеи, которые обсуждались

- Отклонено пользователем как лишнее: условия «префиксов ровно N / свободный суффикс».
- Сделано (1.1.0): кнопка «⟳ Новая база», вкладка «О программе» с обновлениями (как в Awakened PoE Trade).
- Предложено, не сделано: подсветка предпросмотра Awakener's Orb (подсказка при наведении);
  сборка одного `.exe` (PyInstaller, собирать на Windows).
- Известные ограничения: игра суммирует одинаковые строки от разных модов в одну —
  такие строки могут определяться неточно.
